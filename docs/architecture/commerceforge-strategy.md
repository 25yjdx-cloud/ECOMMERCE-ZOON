# استراتيجية CommerceForge

## الغرض ونموذج العمل

CommerceForge نواة تقنية مشتركة لصناعة متاجر إلكترونية احترافية وتسليمها لعملاء مستقلين. الهدف تقليل وقت بناء المتجر مع الحفاظ على جودة التصميم والوظائف وإمكانية صيانة التحسينات في Core.

هذا المشروع ليس SaaS متعدد المستأجرين. مشاركة Core تعني مشاركة مصدر الكود وصيانته فقط، ولا تعني مشاركة بيئة التشغيل أو بيانات العملاء.

## القرارات المعتمدة

- **Backend:** الحفاظ على Laravel وBagisto كأساس backend ما لم يكشف التدقيق عائقًا تقنيًا جوهريًا. لم تُثبت Bagisto بعد، وإصدارات PHP وLaravel وBagisto لم تُعتمد.
- **Storefront:** Next.js وReact وTypeScript، مع Tailwind CSS واتجاه App Router عند توافقه مع المشروع.
- **لوحة المتجر:** تطبيق Next.js/React مخصص لإدارة متجر العميل. لا تستبدلها بلوحة Bagisto الأصلية.
- **القوالب:** خمسة معرّفات رسمية ثابتة في `config/templates/presets.json`. هذا الملف هو مصدر الحقيقة لبيانات تعريف القوالب.
- **تسليم العملاء:** لكل عميل نشر مستقل وقاعدة بيانات مستقلة وإعدادات وأسرار وحسابات دفع وMeta مستقلة.
- **التخصيص:** إعدادات متجر منظمة، مع تعديلات مخصصة مضبوطة عند الحاجة؛ لا يبدأ المشروع بمنشئ صفحات drag-and-drop.
- **Meta Ads:** أولوية عالية بعد تأسيس الاتصال الآمن والواجهات، مع عزل بيانات واعتمادات كل عميل.
- **خارج النطاق الحالي:** SaaS متعدد المستأجرين، وفوترة SaaS، وERP، وPOS.

## مسؤوليات المكونات

1. **Laravel/Bagisto:** إدارة التجارة والمنتجات والطلبات والعملاء والمخزون والدفع والشحن عبر وظائف Bagisto المتاحة وواجهاته المدعومة.
2. **Storefront:** عرض القوالب، وتصفح الكتالوج، والسلة، والشراء، وتجربة العميل.
3. **لوحة العميل:** إدارة متجره ومتابعة بياناته التجارية والمالية، مع صلاحيات منفصلة لكل نشر عميل.
4. **Meta integration:** ربط أصول Meta الخاصة بالعميل وعرض المقاييس المتاحة بعد موافقته، دون كشف الرموز السرية للواجهة.
5. **قوالب الواجهة:** تختلف في البنية وتجربة الاستخدام والخصائص المناسبة للقطاع، وتعيد استخدام الخدمات والسلوك التجاري المشترك.

## سجل القوالب

المصدر الرسمي هو [`config/templates/presets.json`](../../config/templates/presets.json). يحتوي السجل على الأسماء العربية والإنجليزية، والتصنيفات، وحالة البداية، والظهور المقترح في الصفحة الرئيسية، ومسار الصورة المصغرة.

القوالب الخمسة هي:

| المعرّف | الاسم | القطاع المستهدف |
|---|---|---|
| `fashion` | أزياء وموضة | الملابس والأحذية والإكسسوارات |
| `furniture` | أثاث وديكور | الأثاث وديكور المنزل |
| `electronics` | إلكترونيات | الإلكترونيات والأجهزة |
| `grocery` | بقالة وسوبرماركت | البقالة والسوبرماركت |
| `local-brand` | متجر علامة تجارية | الأزياء والعطور والمنتجات المحلية والعناية |

الحالة `planned` تعني أن القالب لم يُنفذ ويُختبر بعد. لا تُغيّر إلى حالة إنجاز إلا بعد اختبار رحلة التسوق ذات الصلة. لا تُغيّر المعرّفات أو مخطط السجل دون موافقة.

## العزل والأمان

- قاعدة بيانات ونشر وإعدادات بيئة منفصلة لكل عميل.
- لا تُشارك حسابات الإدارة أو أسرار الدفع أو رموز Meta بين العملاء.
- تُخزن الأسرار خارج المستودع، ولا تُرسل الرموز طويلة الأمد إلى المتصفح.
- تعتمد الصلاحيات على أقل امتياز، ويجب اختبار منع الوصول المتبادل بين العملاء.
- لا تُعرض أرقام ربح قبل تعريف مصادر التكلفة والخصومات والمرتجعات والمصروفات.
- لا تُعتبر بيانات Meta المنسوبة للإعلانات مساوية تلقائيًا لطلبات المتجر أو إيراداته.

## التقارير المالية

يجب التمييز بين إجمالي المبيعات وصافي المبيعات وتكلفة البضاعة المباعة والربح الإجمالي ومصروفات الإعلان والمصروفات الأخرى.

- الربح الإجمالي = صافي المبيعات - تكلفة البضاعة المباعة.
- الربح التشغيلي التقديري = الربح الإجمالي - الإنفاق الإعلاني - المصروفات الأخرى المسجلة.

تُذكر صراحةً عناصر التكلفة غير المحسوبة، مثل رسوم الدفع أو الشحن أو الضرائب، ولا يوصف التقدير بأنه صافي ربح دقيق إذا كانت البيانات اللازمة ناقصة.

## اللغات والأسواق

دعم العربية RTL والإنجليزية LTR والعملات والتنسيقات المحلية متطلبات للمنتج. تُضبط اللغة والعملة بحسب المتجر؛ أما الأسواق ووسائل الدفع الافتراضية وتفاصيل الامتثال فتحتاج تحديدًا قبل التنفيذ.

## بيئة التطوير

البيئة المستهدفة Windows مع WSL2 وUbuntu وDocker Desktop وDocker Compose وGit وNode.js وPHP وComposer. إصدارات PHP وComposer وNode.js وMySQL وأطر العمل تُحسم بمصفوفة توافق قبل تثبيت الاعتمادات. لا تُرقَّى الإصدارات تلقائيًا.

تم تثبيت Docker وتهيئة WSL2/Ubuntu على جهاز المطور بحسب التحقق المحلي. لا يوجد حاليًا تثبيت Bagisto أو Laravel في المشروع، ولا يتطلب بدء تدقيق Phase 0 التسجيل في Bagisto.

## خارطة التنفيذ

1. **Phase 0 — Audit & Foundation Review:** تدقيق المستودع والقرارات والبيئة؛ لا تنفيذ متجر ولا تثبيتات غير معتمدة.
2. **Phase 1 — Architecture Foundation:** اعتماد مصفوفة الإصدارات والعقود والبيئة والحدود الأمنية، ثم إنشاء الأساس بموافقة المستخدم.
3. **Phase 2 — لوحة المتجر:** تطوير لوحة Next.js وربطها بواجهات Bagisto المتحقق منها.
4. **Phase 3 — التحليلات:** تقارير مبيعات وربح بقواعد مالية موثقة وبيانات حقيقية.
5. **Phase 4 — Meta Ads:** التفويض الآمن وعزل الحسابات وجلب Insights ومعالجة الانتهاء والأخطاء.
6. **Phase 5 — Theme Engine:** سجل القوالب والتهيئة والمكونات المشتركة.
7. **Phase 6 — Fashion:** اقتراح اتجاه بصري ومراجعته قبل اعتماد التنفيذ، ثم اختبار رحلة التسوق.
8. **Phase 7 — القوالب الأربعة الأخرى:** تنفيذ كل قالب بتجربة قطاعية مختلفة.
9. **Phase 8 — التسليم:** إعداد النشر المستقل والنطاق والنسخ الاحتياطي والترقيات لكل عميل.
10. **Phase 9–10 — الاختبار والتوثيق والإصدار:** اختبارات وظيفية وأمنية وRTL/LTR، ثم توثيق النتائج دون ادعاء إنجاز غير متحقق.

## الحالة الراهنة وحدود هذه الوثيقة

هذه وثيقة استراتيجية وسجل تعريف القوالب، وليستا تطبيقًا تشغيليًا. لا توجد حاليًا خدمات Laravel/Bagisto أو تطبيقات Next.js مكتملة أو واجهات API أو قوالب جاهزة. تبقى تفاصيل الإصدارات، والمصادقة، وعقود API، والنشر الفعلي قرارات تأسيسية يجب مراجعتها قبل التنفيذ.
